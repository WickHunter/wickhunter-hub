# Hub payout and Earn ledger follow-up (source only)

`fd4cfee` and `94ebcfa` address DM-23/DH-5 and DH-21 without a Hub deployment, live Stripe request, payment or customer message.

The payout scheduler previously parsed both full Earn ledgers and sorted all jobs every minute. Each checked payout made a separate full-ledger atomic rewrite and fsync even if Stripe returned the same status. It now remembers the atomic file version and next posted check time, reuses a version-matched candidate snapshot, and rescans on any file replacement or process restart. Processing payouts still poll on each run. At most 100 due jobs per rail are read from Stripe and applied in one durable transaction. A financial-identity change during an awaited provider read refuses settlement; an unknown result or missing original paid entry cannot release a reservation. A crash before batch commit leaves all original holds and jobs available for replay.

A fixture with 120 posted jobs and roughly 0.9 MB of retained ledger history measured one ledger parse, zero Stripe reads and zero ledger writes during 60 idle one-minute ticks. At the six-hour deadline the first 100 checks used one full-ledger save and the remaining 20 used one more, instead of one save per job. A new service instance resumed the schedule from the ledger; subsequent Stripe `returned` statuses restored each payout once. Repeating an unchanged `processing` result at the same instant did not rewrite the ledger. This is a local fixture measurement, not a production-size or network-latency claim.

DH-21's unrelated signed events still require Stripe invoice/subscription reads when no local proof identifies their product. Once those reads prove no financial state changed, the event ID goes to a bounded, mode-scoped replay sidecar instead of the financial ledger. The sidecar has no money authority: if lost, Stripe is read again. Relevant events continue to write their seen marker with financial state, and no invoice or ledger entry is discarded. A foreign-price event left the financial ledger version unchanged and its replay made no Stripe call.

`npm run build` passed. The focused payout fixture passed 4/4 and Earn Stripe passed 18/18. The full Hub gate passed 74/74 with Homebrew Bash on `PATH` and `LIQHUNTER_BOT_MODULE` pointed at the built Alpha percentile module. Without those local tool-path settings, the only two failures were the backup script invoking Bash `mapfile` under macOS Bash 3.2 and the percentile parity test's Linux-default app path; neither touches this change.
